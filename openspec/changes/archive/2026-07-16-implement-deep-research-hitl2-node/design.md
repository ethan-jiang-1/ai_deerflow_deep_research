## Context

Change 12 completed the targeted evidence loop. HITL2 is the final human-in-the-loop
decision gate: it presents a structured brief of accepted findings to the user, suspends
the graph via LangGraph interrupt, and routes based on the user's decision. The existing
fake HITL2 already implements the full interrupt/resume/response-validation pipeline
using `PendingResearchInterrupt`, `Hitl2Decision`, `AcceptedHumanResponse`, and
`InternalCancelDecision` — all the infrastructure is in place. The real node only needs
to replace the fixture briefing text with a brief built from actual accepted findings.

HITL2 sits between `wave2_synthesis` and `rerun`/`readiness`/`stop` in the topology.
It is a graph-owned HITL node: it may call `langgraph.types.interrupt`, but it runs
no LLM, calls no tools, and writes no sandbox files. It reads from checkpoint state
and writes only checkpointed control fields.

## Goals / Non-Goals

**Goals:**
- Build a deterministic brief from accepted findings, synthesis gaps, and critic
  verdicts. The brief SHALL contain: summary of confirmed findings, key uncertainties,
  unresolved gaps with priority, and available actions.
- Present the brief through the existing `PendingResearchInterrupt` / `HumanInputRequest`
  choice-mode mechanism already implemented in the fake.
- Parse the user's decision through `AcceptedHumanResponse` with request-id binding,
  and route to one of five edges: `proceed`, `revise_view`, `repair`, `rerun`, `stop`.
- Detect stale resume via the existing `request_id` mechanism (encodes generation),
  requiring no new checkpoint fields.
- Handle cancellation (`InternalCancelDecision`) identically to the fake.

**Non-Goals:**
- No LLM call — HITL2 is code-only, no model invocation.
- No sandbox file writes.
- No modification to `backend/` or `frontend/`.
- No rerun invalidation, readiness gate, or final delivery logic.

## Decisions

### Decision 1: Reuse the fake's interrupt/resume pipeline exactly

The real factory uses the same `PendingResearchInterrupt` → `HumanInputRequest(CHOICE, options=Hitl2Decision)` → `interrupt()` → `AcceptedHumanResponse` → `Hitl2Decision` flow as the fake. The only difference is the briefing text: instead of a fixture message, it is built from actual accepted findings and synthesis output.

Why: the fake already correctly implements request-id generation, response validation,
cancellation handling, consumed-message tracking, and terminal-state transitions.
Duplicating or bypassing this would be a regression.

### Decision 2: Brief builder is deterministic, code-only

The brief builder reads from checkpoint state fields (`accepted_submission_refs`,
`synthesis_gaps`, `critic_verdicts`) and formats them into a human-readable summary.
No LLM call, no external data — the content is projection of already-validated state.

Why: HITL2 is a control node, not a research node. Introducing an LLM here would add
latency, cost, and non-determinism to a decision that should be based on the same
findings the user has been seeing accumulate through the research.

### Decision 3: Stale-resume detection uses existing request-id mechanism

The `request_id` generated by `make_hitl_request_id(research_id, phase, generation, ordinal)`
already encodes the generation. On resume, the node validates `response.request_id == request_id`.
If the generation changed between interrupt and resume (e.g., after a rerun), the
new request_id won't match the old response, providing stale-resume detection without
additional state fields. No new checkpoint fields (`pending_user`, `brief_hash`) are
needed — the existing mechanism is sufficient.

Why: the HITL1 fake, HITL1 real, and HITL2 fake already use this pattern. Adding new
state fields would be over-engineering.

### Decision 4: Recipe requires wave2_synthesis real

Real HITL2 requires `wave2_synthesis=real` (which transitively requires the full
chain through wave0/wave1/targeted_evidence). Topology is unchanged.

## Risks / Trade-offs

- **Brief is code-only**: may miss nuance a model could provide. Acceptable because
  the user already saw findings accumulate in prior phases; the brief is a summary,
  not a discovery step.
- **State written before interrupt**: adds a checkpoint write. Acceptable because
  HITL2 is a human-paced interaction where correctness > latency.

## Open Questions

- Whether to include critic verdict summaries in the brief. Deferred; start with
  findings + gaps only, add critic data in a later refinement.
